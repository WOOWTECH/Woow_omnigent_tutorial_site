Chapter 16

為何需要本章

第 15 章的結論如果是「我需要自己的執行端」，這一章就是把它接上去的完整流程。做完之後，Composer 底部的主機選單裡會多出一台，前面帶著綠點，你可以把工作交給它。

整件事只有一條註冊指令，難的不是指令本身，而是它前後那些容易漏掉的條件：伺服器網址要填對、機器上要先有兩個套件、指令跑起來之後不能關掉。這一章按順序把它們排好。

這條指令會讓一個代理擁有那台機器的檔案讀寫能力。在自己的主力工作機上執行之前，先讀完第 12 章的規則與第 14 章的安全基線。

「註冊」到底做了什麼

指令的名字叫 omnigent host，做的事是：在這台機器上啟動一個執行端行程，讓它主動撥一條連線回伺服器，並且在伺服器的主機清單裡登記自己。

撥入（dial-in）：由內往外建立連線。註冊之後的通道是從你的機器打向伺服器的，所以你這一側不需要固定 IP，也不需要在路由器或防火牆上開任何入站規則。

三個推論，先記下來：

  • 需要打得通的是伺服器那一側的服務埠。附加元件版預設是區網上的 8000，那個埠同時負責 API、執行端撥入與這條註冊指令。
  • 指令是常駐的。它不是跑完就結束的安裝程式，而是要一直活著的行程；它停了，主機就離線。
  • 憑證是這台機器自己的。伺服器端設定的金鑰只給伺服器行程用，執行端帶自己的。

開始之前

備齊四樣東西再開始，中途缺一樣就得從頭來。

要準備的內容怎麼取得
伺服器網址執行端要撥回去的那個位址，含埠號附加元件版預設是區網主機名加上 8000；有設定 base_url 的話以那個為準
網路可達性這台機器打得到上面那個網址同一個區域網路即可；跨網際網路要先有一條通道
Node.js 與 npm用來安裝 pi 代理工具依作業系統各自安裝，本書不涵蓋
Python 與 pip用來安裝 omnigent 執行端同上

先用瀏覽器在那台機器上打開伺服器網址試一次。看得到登入畫面，代表網路這一關過了；打不開就先解決網路，不要急著跑指令。

註冊流程

  1. 確認伺服器網址

    附加元件版的服務埠是 8000，官方文件在埠表裡寫明它負責三件事：API、通道撥入、以及 omnigent host。設定裡的 base_url 留空時，系統用的是區網主機名加上這個埠。

    如果管理者已經把 base_url 改成一個公開網域（第 14 章講過為什麼要改），那就用那個網域，不要用區網位址。兩者混用會導致註冊成功但邀請連結指錯地方。

  2. 在那台機器上裝好兩個套件

    一個是實際幹活的 pi 代理工具，一個是執行端本身。附加元件文件裡列出的指令是：

    npm install -g @earendil-works/pi-coding-agent@0.85.1

    pip install omnigent==0.12.0

    版本號請照你自己那一版的文件填。三種部署打包的伺服器版本本來就有落差，本書的固定來源指向的是特定的一次 commit，你手上的可能更新。版本對不上時最常見的症狀是註冊成功但功能行為怪異。

  3. 執行註冊指令

    把網址換成上一步確認過的那一個：

    omnigent host --server http://homeassistant.local:8000

    這條指令會開一條回伺服器的通道並登記這台機器。它跑起來之後不會結束，這是正常的——讓它留在終端機裡。

  4. 回瀏覽器確認主機出現了

    開一個新 session，展開 Composer 底部最左邊的主機選單。剛註冊的那台應該出現在清單裡，名字前面帶一個綠點表示線上。

    選它，然後把旁邊的工作目錄選單改成你要讓代理動的那個目錄。第 7 章講工作目錄的挑法，第 6 章講整排選單的每一個位置。

  5. 挑一個框架，開一個小 session 試跑

    在 Runs with 選單裡挑一個框架。這台機器上沒設定好的項目會標著橘色的 needs setup 徽章，先避開它們，挑一個沒有徽章的。

    然後丟一個小到不可能出錯的需求，例如請它列出這個工作目錄底下有哪些檔案。有回應就代表整條路通了。

  6. 決定它要不要長期活著

    終端機關掉、機器休眠或重開，這個行程就沒了，主機會在清單裡變成離線。臨時用一次沒差；要讓第 10 章的排程任務半夜自己開工，就得把它做成開機自動啟動的服務。Rootless Podman 套件就是用一個常駐容器達成這件事，做法見第 21 章。

怎麼確認做對了

三個地方可以互相印證，不要只看其中一個。

  • Composer 底部的主機選單：那台機器出現在清單裡，名字前面有綠點。這是最直接的一個。
  • Settings 的 Import sessions 頁：Machine 下拉選單裡會出現這台機器，而且帶著 ONLINE 徽章。這一頁本來的用途是把那台機器上既有的本地對話拉進 Omnigent，但它同時是一個很好的線上狀態驗證點。
  • 真的跑一次：前兩項都只證明「連線在」，不證明「做得了事」。開一個小 session 拿到回應，才算完整。

Import sessions 頁還有兩個欄位：Harness 可以只挑某一種框架，How many recent sessions 決定往回抓幾筆。已經匯入過的會自動跳過，重複按不會產生重複資料。

註冊之後會變成什麼樣子

主機接上之後，好幾個原本按不動的地方會突然活起來，先有個心理準備。

  • 框架選單不再全是灰的。目錄分成框架與代理兩區，你這台機器上設定好的那些會變成可選。第 17 章逐一介紹它們的差別。
  • 排程任務有地方可以跑了。新增自動化時的主機欄位預設是「觸發時再決定」，意思是交給當時連著的主機執行——在你接上第一台之前，那個預設值等於沒有效果。
  • 工作目錄與 worktree 選單開始有意義。它們列的是那台機器上的目錄，換一台主機，可選的目錄就換一批。

如果之後還會接第二台、第三台，現在就決定命名規則。正式站的主機名稱把機器角色跟編號寫在一起，選單裡一眼就分得出誰是誰；名字取得隨便，第 18 章要你清掉一台失聯主機時，你會不確定該刪哪個。

故障排除

  • 徵狀：主機選單一直是空的。先確認你是不是裝了純伺服器的版本——附加元件版不打包執行端，清單空的是預期行為，這正是本章存在的理由。已經跑過註冊指令的話，回終端機看那個行程還在不在。
  • 徵狀：註冊指令連不上伺服器。兩種常見原因：主機名解析不到，改用 IP 位址試一次；或者伺服器的服務埠沒有對這台機器開放。用瀏覽器打開同一個網址是最快的判斷方式。
  • 徵狀：註冊成功，但對話丟出去沒有任何回應。官方疑難排解把這一條歸因為 pi 的擴充衝突，處置方式是清掉執行端那台機器上的 ~/.pi-agent/plugins/ 目錄，並從 ~/.pi-agent/auth.json 裡移除 openai-codex，然後重新連線。
  • 徵狀：主機列在清單裡，但是灰的。那個行程停了。終端機被關掉、機器休眠、網路換過，都會造成這個結果。重新跑一次註冊指令即可，重複註冊不會產生第二台。
  • 徵狀：框架全部標著 needs setup。連線沒問題，是那台機器上的框架還沒設定好認證。這是第 17 章的題目，跟註冊無關。你也可以在外觀設定裡打開隱藏未設定框架，讓選單只留下能用的那幾個。
  • 徵狀：邀請連結給同事之後打不開。伺服器的 base_url 還指著區網位址。這要在伺服器那一側改，不是在執行端改，做法見第 14 章。

常見問題

這一章的內容適用於哪些部署方式？

註冊流程本身三種都一樣，因為執行端撥入的是同一套伺服器。差別在你需不需要做：純伺服器的附加元件版一定要做；自帶執行端的部署方式裝完就有一台可用，只有在你想額外接自己的機器時才需要這一章。

我需要在防火牆或路由器上開埠嗎？

執行端這一側不用。連線是由你的機器主動撥向伺服器，所以你不需要固定 IP，也不需要任何入站規則。要能被打到的是伺服器那一側的服務埠——那是管理者的事，第 14 章有完整的埠對照表。

註冊之後，代理是不是就能碰我整台機器的檔案？

能碰到的範圍由兩件事決定：你在 session 裡選的工作目錄，以及有沒有規則在擋。預設沒有任何全域規則啟用，所以請務必先看第 12 章，至少把限制寫入範圍或危險指令攔截其中一條打開，再把工作目錄選在專案資料夾而不是家目錄。

同一台機器可以註冊兩次嗎？

重跑註冊指令不會多出第二台，它會重新接上原本那一台。真正會產生多餘項目的是另一種情況：機器換了識別或重建之後，舊的那筆會留在清單裡且再也連不上。那屬於第 18 章要處理的失聯主機。

如果畫面跟書上不一樣，是版本差異還是我做錯了？

指令裡的兩個版本號最容易對不上，那是版本差異，照你自己那一版的文件填就好。但如果 Composer 底部沒有那排選單，或是 Settings 裡找不到 Import sessions，比較可能是你在的畫面不對——那排選單只出現在新 session 的輸入區，Import sessions 則在 Settings 的個人分頁那一組裡。
