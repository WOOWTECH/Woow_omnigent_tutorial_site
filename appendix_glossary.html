這份對照表怎麼用

Omnigent 的介面是英文的，這本書是中文的。中間那道翻譯落差在你只是點按鈕的時候不成問題，但只要你開始讀英文的原始文件、看記錄檔、或跟別人討論，落差就會變成阻力。

這份附錄把全書出現過的名詞收成幾張中文 → English → 一句話定義的表，按用途分四類。它的用途不是從頭讀，而是查：讀到一個詞卡住，翻到這裡，看完一句話定義，回去繼續讀。

每一列都標了章次。一句話定義只夠讓你不卡住，要真的搞懂那個概念，還是要回去讀那一章。

先把四個核心名詞釘死

整本書最容易搞混的就是這四個，而且它們常常在同一個句子裡出現。第 3 章用一整章講它們，這裡是壓縮版。

中文English一句話定義
指揮中心Server存帳號、Session、排程與成本紀錄的那一台，網頁介面也由它提供
主機Host被指揮的那台機器，在介面上是你可以挑選的執行目標
執行端Runner常駐在主機上的行程，負責接下任務並在那台機器上真的跑起來
框架Harness實際寫程式的 AI 工具，例如 Claude Code、Codex、Pi
後設框架meta-harness管理多個框架的那一層，也就是 Omnigent 自己；它不含模型

最短的區分法：Server 是指揮的人，Host 是被指揮的機器，Runner 是那台機器上聽命令的人，Harness 是他手上的工具。一台主機上通常只有一個執行端，但同一個執行端可以提供好幾種框架。

查詞之前先知道三件事

  • 產品名與框架名一律不譯：Omnigent、Home Assistant、Claude Code、Codex、Pi、Podman、Helm、k3s 這些在中文句子裡也維持原字。硬翻只會讓你在英文文件裡找不到對應。
  • 介面標籤保留英文原字：介面上沒有中文，所以本書提到某個按鈕或分頁時，會用它畫面上的英文原字。中文只出現在解釋裡。
  • 「版本」這個詞有兩層意思：一個是部署套件自己的版本（例如附加元件 0.1.15），另一個是它裡面那份 Omnigent 核心的版本（例如 0.12.0）。看到版本號先問是哪一層，附錄 A 有對照表。

查詞的四個步驟

  1. 先判斷它屬於哪一類

    看得到、點得到的是介面名詞；跟「誰去跑、用什麼跑」有關的是執行名詞；跟「准不准、花多少」有關的是治理名詞；只在安裝時出現的是部署名詞。分類錯了會找很久。

  2. 用英文原字找

    介面是英文的，記錄檔也是英文的。表格的第二欄就是給你這樣用的：先在英文那一欄掃過去，比在中文欄找快得多，也不會被不同的譯法卡住。

  3. 讀完一句話定義就回去

    一句話定義的目的是讓你不卡住，不是讓你搞懂。看完就回到原本在讀的那一段，讀完整段之後如果還是不確定，再照章次翻過去。

  4. 跟英文文件對照時保留原字

    要去讀上游或部署倉庫的英文文件時，用表格第二欄的原字搜尋。中文譯名是本書為了讀起來順而取的，上游文件裡不存在。

  5. 表裡沒有的詞怎麼辦

    這份表只收本書用得到的。介面上出現、書裡沒提到的詞，代表本書的實機記錄沒有涵蓋到它——那種情況不要猜，以你自己在畫面上看到的行為為準。

自我檢測

不用背這份表。但下面四題答不出來的話，回去讀對應的章。

  • 用一句話說出 Host 和 Runner 的差別。（提示：一個是機器，一個是機器上的行程）
  • 說出 Harness 和 Model 各自決定什麼。（提示：一個是工具，一個是工具背後呼叫的模型）
  • 說出 Project、Session、Worktree 三者的包含關係。（提示：只有前兩個有包含關係，第三個是 Git 那邊的概念）
  • 說出 ASK 和 DENY 的差別，以及為什麼排程任務不該碰到 ASK。

最常搞混的五組配對

  • Server 與 Host：Server 只有一個，是你登入的那個網址；Host 可以有很多個，是清單裡讓你挑的機器。安裝時裝的是 Server，接上去的是 Host。
  • Host 與 Runner：Host 是機器，Runner 是那台機器上跑著的行程。主機顯示離線幾乎都是 Runner 掛了，機器本身還開著。
  • Harness、Agent 與 Model：介面上 Harness 與 Agent 是同一個下拉選單裡的兩區，Model 是另一個選單。Harness 是工具，Agent 是預先組好的多代理選項，Model 是背後被呼叫的模型。三者可以獨立更換，這也是排查時「一次只換一項」的依據。
  • Project、Session 與 Worktree：Project 裝 Session，這是介面上的分組；Worktree 是 Git 的平行副本，跟 Project 沒有關係。設定裡可以要求每個新 Session 都開一個新的 Worktree，這是兩個系統的交界處，也是最常被誤會成「我的檔案不見了」的地方。
  • 套件版本與核心版本：附加元件、Podman 套件、Helm chart 各有自己的版號，裡面包的 Omnigent 核心又是另一個版號。兩者不會同步，看到數字先問是哪一層。

常見問題

為什麼有些詞不翻成中文？

因為介面沒有中文。把 Composer 翻成「編寫器」，你在畫面上找不到那個字，去搜尋英文文件也搜不到。本書的做法是：產品名、框架名、按鈕與分頁的標籤保留原字，解釋用中文。這份表的第二欄就是那些原字。

Agent 和 Harness 到底差在哪？

它們在介面上是同一個下拉選單裡的兩個區塊。Harness 那區是單一的 AI 編碼工具，Pi、Claude Code、Codex 這些；Agent 那區是預先組好的多代理選項，例如多代理協作或多代理辯論。你每個 Session 只會從其中挑一個。要選哪一種的判斷在第 6 章與第 17 章。

表裡的詞在我的畫面上找不到怎麼辦？

先當成版本差異。這份表對應的是 2026-09-09 那次實機記錄，而三種部署方式的版本本來就不同步。以你畫面上實際看到的為準，不要為了對上書而去改設定。真的差很多的話，看該部署的固定來源確認你手上是哪一版。

我只是要用，需要記住這些嗎？

不需要。真正必須分清楚的只有第一張表那四個——Server、Host、Runner、Harness——因為後面每一個設定畫面都預設你知道它們的差別。其餘的用到再查就好，這份表存在的目的就是讓你不用記。

英文版的書會用同一套譯名嗎？

方向是相反的：英文版直接用原字，不需要譯名。本書的翻譯政策明訂產品名、框架名、設定鍵、指令、檔名、版本與佔位值都保持原樣，而且不會把任何憑證寫成看起來可用的值。中英兩版的章節結構、表格列數與 FAQ 則數都保持一致。
