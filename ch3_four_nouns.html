第 3 章

Server、Runner、Host、Harness：四個名詞一次搞懂

為何需要本章

接下來十九章裡，有四個詞會不斷出現：Server、Host、Runner、Harness。它們長得都很像「跑東西的地方」，但指的是四件完全不同的事。

混淆它們的代價很具體。最常見的一種是：你交辦了一件事，代理回你「找不到這個檔案」，你確定檔案就在眼前——因為它在你的筆電上，而代理跑在另一台機器上。這不是 bug，是你選錯了 Host。

這一章沒有要你設定任何東西，只要你能把這四個詞各自對應到畫面上的哪一個位置。

核心觀念：一句話定義四個名詞

先把四句話讀完，再看它們怎麼串起來。

Server（伺服器）：你瀏覽器連上去的那一套 Omnigent 本身。所有 session、Project、設定、成本紀錄都存在這裡。你在網址列看到的就是它。

Host（主機）：被指揮的那台機器。代理實際讀寫檔案、跑指令的地方。畫面上它有名字，例如 Pi Web ChatGPT (pi5)。

Runner（執行端）：住在 Host 上、負責跟 Server 保持連線、聽命令並實際動手的常駐程式。沒有它，那台機器對 Server 來說就不存在。

Harness（框架）：真正會寫程式的那個 AI 工具，例如 Claude Code、Codex、Pi。Omnigent 自己不寫程式，寫程式的是它。

串起來就是一句話：你在 Server 上派工，Server 透過 Host 上的 Runner，去啟動一個 Harness，讓它在那台機器上幹活。四個名詞是一條鏈，缺任何一環都動不了。

四個名詞對照表

如果只能記一張表，記這張。

名詞它是什麼在畫面上哪裡看到缺了它會怎樣
Server指揮中心，存放全部紀錄瀏覽器網址列；整個介面就是它連不上，什麼都做不了
Host被指揮的機器輸入區底部第一個下拉，例 Pi Web ChatGPT (pi5)沒有機器可派工，清單是空的
RunnerHost 上的常駐程式沒有直接寫出這個字；你看到的是名字前面的綠點與 ONLINE 徽章Host 出現在清單裡但沒有綠點，派工過去不會有反應
Harness實際幹活的 AI 工具Runs with 下拉的第一區指揮台是空的，沒有東西可以派

一個記憶方法：Server 是辦公室，Host 是工地，Runner 是工地上那支永遠開著的對講機，Harness 是被派去工地的工人。對講機沒開，辦公室就叫不動任何人。

它們在畫面上分別長什麼樣

四個名詞裡有三個集中在同一個地方：新對話輸入區的底部。那裡有三個並排的下拉選單。

  • 第一個是 Host：顯示機器名稱，前面有一個綠點代表線上，例如 Pi Web ChatGPT (pi5)。
  • 第二個是工作目錄：代理會在這台機器的哪個資料夾裡動手，例如 home。
  • 第三個是 Worktree：Git 的工作樹，決定代理改的是原本那份還是另外開一份。第 7 章會詳談。

Harness 則在另一個下拉，名字叫 Runs with。打開它會看到清單分成兩區：上面是 Harnesses，下面是 Agents。

分區清單內容數量
HarnessesClaude Code、Codex、Pi 三個直接顯示；其餘收在 More 底下：OpenCode、Cursor、Antigravity、Kiro、Qwen Code、Goose、Kimi、Hermes11
AgentsPolly（多代理協作寫程式）、Debby（多代理互相辯論）、Grok Build、Devin，另有 Custom agents 可展開4 加自訂

清單裡沒有在那台 Host 上設定好的項目，會被標上橘色的 needs setup 徽章。這個徽章是跟著 Host 走的：同一個 Harness 在 A 機器上設好了、在 B 機器上沒設，換 Host 之後徽章就會出現。

覺得清單太長，可以到設定的 Appearance 打開 Hide unconfigured harnesses。打開之後那些標 needs setup 的項目會直接消失，而不是被標記。清單變短了不是壞掉，是這個開關。

Runner 是唯一一個介面上沒有直接寫出名字的。你在兩個地方會看到它存在的證據：Host 名稱前面的綠點，以及設定裡 Import sessions 分頁的 Machine 欄位，那裡機器名稱旁邊會掛一個 ONLINE 徽章。

開始之前

這一章全程只看不改，所以要準備的東西很少：

  • 已經照第 2 章登入，而且看得到 New session 畫面與底下那排下拉。
  • 手邊有紙筆或一個記事檔。等一下你會抄下四樣東西：Server 網址、Host 名稱、哪幾台是綠點、以及可用的 Harness。
  • 知道你將來要處理的檔案放在哪一台機器上。不知道也沒關係，這一章正好會讓你發現這件事必須先搞清楚。

如果你的環境目前一台 Host 都沒有，這一章還是讀得完，只是第 2 到第 5 步會看到空清單。名詞觀念先建立起來，等第 16 章接上第一台機器再回來對一次畫面。

操作步驟：五分鐘把四個名詞對到畫面上

這一輪全部只看不改。目標是讓每個名詞在你腦中都有一個對應的畫面位置。

  1. 找出 Server

    看瀏覽器網址列。那個網址就是 Server。把它記下來或加到書籤——之後你所有的 session 都住在這裡，換一個網址就是換一整套資料。

  2. 找出 Host

    回到 New session，看輸入框底下第一個下拉，展開它。清單裡每一台都是一個 Host。注意哪些名字前面有綠點，那些才是現在叫得動的。

  3. 找出 Runner 的證據

    進設定的 Import sessions 分頁，看 Machine 欄位。線上的機器旁邊會有 ONLINE 徽章。這個徽章跟第 2 步的綠點是同一件事的兩種畫法：那台機器上的 Runner 正在跑。

  4. 找出 Harness

    回到輸入區，展開 Runs with。數一數上半區有幾個（連同 More 底下的，共十一個），下半區的 Agents 有幾個（四個加上自訂）。順便看看哪些被標了 needs setup，那些是現在不能用的。

  5. 把工作目錄看清楚

    展開輸入區底部第二個下拉。這是代理將要動手的資料夾。這一格選錯，是新手最常見的「檔案不見了」原因，比選錯 Host 更常發生，因為選錯 Host 至少會很明顯。

怎麼確認你分清楚了

用自己的話回答這五題。答不出來的往回翻，不要硬往下讀第 4 章。

  • 你的 Server 網址是什麼？
  • 你手上有幾台 Host？其中幾台現在是綠點？
  • 綠點代表什麼在跑？（答案是那台機器上的 Runner）
  • Runs with 清單裡，你這台 Host 上有哪幾個 Harness 沒有標 needs setup？
  • 如果你要代理讀你筆電上的一個檔案，光把檔名貼給它夠不夠？（不夠，那個檔案必須在某台 Host 上）

故障排除

  • Host 下拉是空的：這套 Server 底下還沒有註冊任何機器。這不是設定跑掉，是少了一整個步驟。第 16 章專門講怎麼註冊第一台主機，第 15 章先說明為什麼需要。
  • Host 在清單裡，但名字前面沒有綠點：機器登記過，但它上面的 Runner 現在沒有在跑，或跑起來了但連不回 Server。派工過去不會有反應。第 18 章有完整的排查順序。
  • 想用的 Harness 標著 needs setup：那個 AI 工具在這台 Host 上還沒設定好，換一台 Host 可能就正常。要在這台補上設定，看第 6 章與第 17 章。
  • Runs with 清單比書上列的短：先檢查設定的 Appearance 裡 Hide unconfigured harnesses 是不是開著。它會把未設定的項目整個藏起來，不是刪掉。
  • 代理說找不到檔案，但你確定檔案存在：依序檢查三件事——選的 Host 是不是你以為的那一台、工作目錄是不是對的那一層、以及檔案是不是根本在你自己的電腦上而不在任何 Host 上。第三種情況最常見，也最容易被誤判成 bug。
  • 換了 Host 之後，原本用得好好的 Harness 不見了：正常。needs setup 與可用清單都是跟著 Host 走的，不是全站共用一份設定。

常見問題

Runner 跟 Host 是同一件事嗎？

不是。Host 是那台機器，Runner 是機器上跑著的那支程式。同一台機器，Runner 停掉它就變成離線的 Host——名字還在清單裡，但前面沒有綠點，派工過去不會有反應。把它想成機器與機器上的對講機，機器沒搬走，但對講機關了。

一台 Host 上可以有好幾個 Harness 嗎？

可以，而且這是常態。Runs with 清單是每次開 session 時逐次挑的，同一台機器上可以裝好幾個 AI 工具，哪個設定好了就哪個可用，沒設定好的會標 needs setup。反過來，同一個工具也可以裝在好幾台 Host 上。

Agents 那一區的 Polly、Debby 算不算 Harness？

介面把它們放在同一個 Runs with 下拉裡，但分成兩區：上面標 Harnesses，下面標 Agents，底下還有 Custom agents 可以展開。從你的操作角度看，兩區都是「可以派工的對象」，選法一模一樣。本書在需要精確區分的地方會分開講，其餘場合統稱可派工對象。

Server 重開的話，跑到一半的 session 會怎樣？

本書的實機記錄沒有測過這個情境，所以這裡不給結論。可以確定的是紀錄存在 Server 上，而執行發生在 Host 上，兩邊是分開的。如果你正在評估重開的風險，第 18 章與附錄 B 有相關的排查方向，但實際行為請以你自己那套環境的實測為準。

Host 下拉裡那些名字是誰取的？

是註冊那台機器的時候取的，所以你會看到像 Pi Web ChatGPT (pi5) 這種混了用途與編號的名字。名字只是給人看的標籤，跟機器的能力無關。多台機器的環境裡，取名取得夠清楚會直接減少選錯 Host 的次數，第 16 章註冊主機時會再提醒一次。
