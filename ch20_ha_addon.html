第 20 章

部署方式一：Home Assistant 附加元件

為何需要本章

如果你手上已經有一台跑 Home Assistant OS 的機器，這是三種部署裡最短的一條路：加一個倉庫、按一次安裝、填兩個欄位、按開始。不用開終端機，也不用先懂容器。

但有一個邊界要先講清楚。這個附加元件只裝伺服器，不裝執行端。裝完你會得到一個能登入的介面，然後主機清單是空的——還沒有任何一台機器願意接工作。本章帶你把伺服器裝起來、把設定頁每個欄位弄懂、選對進入方式，最後接上第一台真的會幹活的機器。

還沒決定用哪一種部署，先回第 19 章的決策表。三種都跑同一套介面，差別在你願意維運到什麼程度。

附加元件裡面裝了什麼

Home Assistant 的附加元件（add-on）就是一個由 Supervisor 管理的容器。這一個容器裡塞了四樣東西。

元件版本在裡面做什麼
omnigent0.12.0編排伺服器本體
PostgreSQL16內建資料庫，只綁 loopback，資料放在 /data/postgres
nginxlatest把網頁介面的路徑改寫成側邊欄面板能用的形式
s6-overlay3.2.1.0容器內的行程管理，負責啟動順序

伺服器版建置（server-only build）：只含編排伺服器與網頁介面，不含 pi、Claude Code、Codex 的命令列，也不含執行端。外部執行端自己撥進來註冊。這個取捨換到的是映像檔維持在四百 MB 以內。

按下開始之後，容器內部依序做六件事：讀設定檔、初始化資料庫叢集、啟動資料庫、在 0.0.0.0:8000 啟動伺服器、用你填的帳密建立第一個管理員、由 nginx 把面板端起來。第一次開機要初始化資料庫，會花上三十到六十秒。

版本落差是已知的。本書鎖定的附加元件版本是 0.1.15，它裡面的 Omnigent 是 0.12.0；第 21、22 章那兩種部署在同一份來源鎖定裡是 0.11.0。附加元件版本號和它包起來的 Omnigent 版本號是兩回事，不要混用。

開始之前

動手前先確認這五件事，缺一件都會在中途卡住。

  • 一台跑 Home Assistant OS 或 Supervised 的機器。附加元件只支援 amd64 與 aarch64
  • 你的帳號是管理員，看得到「設定 → 附加元件」
  • 磁碟留餘裕。內建資料庫會在 /data 底下建整個叢集，隨 session 累積長大
  • 另外一台機器當執行端。可以是你的筆電，也可以是同一台機器上的其他附加元件；沒有它，裝完只是一個空的指揮台
  • 要讓家裡以外的機器連進來，先把 Cloudflared 附加元件準備好

執行端怎麼挑、註冊之後會發生什麼事，第 15、16 章講得比這裡細。本章只走最短路徑。

安裝步驟

  1. 把倉庫加進附加元件商店

    設定 → 附加元件 → 附加元件商店，右上角三點選單 → 儲存庫，貼上 https://github.com/WOOWTECH/Woow_ha_omnigent_addon 後按新增。商店頁重新整理後會多出一個「Woow Omnigent」區塊。

  2. 安裝 Woow Omnigent

    點進去按安裝。Supervisor 會依機器架構拉對應映像檔，時間取決於你的網路。安裝完成前先不要按開始。

  3. 在設定分頁填好管理員帳密

    把 admin_username 與 admin_password 改成你自己的值。不要沿用安裝預設值——那組值公開在原始碼裡，任何看得到倉庫的人都知道它是什麼。填完按儲存。

  4. 按開始，等三十到六十秒

    第一次開機比之後每次啟動都慢。這段時間切到日誌分頁看它跑到哪；資料庫初始化的錯誤訊息會出現在每次開機日誌的最上面。

  5. 從側邊欄開面板登入

    準備好之後左側會多一個「Woow Omnigent」面板。用上一步的帳密登入，看到 New session、Automations、Inbox、Usage 四個入口就是成功了。

  6. 接上第一台執行端

    到另一台機器上裝好執行端所需套件，執行 omnigent host --server http://homeassistant.local:8000。這條指令會從那台機器往附加元件開一條通道並註冊成一台主機。回介面重新整理，主機選單裡就會出現它。

設定頁的每個欄位

欄位型別作用
admin_username字串第一次開機時建立的本機管理員帳號
admin_password密碼這組管理員的登入密碼。安裝預設值務必改掉
base_url選填字串執行端撥進來時用的公開網址。留空等於 http://homeassistant.local:8000
features選填字串逗號分隔的功能旗標，轉成 OMNIGENT_FEATURES= 傳進伺服器
env_vars清單任意環境變數直通，每一筆是一組 key 與 value

三個功能旗標有記載：usage_page 開啟用量報表分頁、web_harness_setup 開啟每台主機的框架設定介面、harness_install 允許從網頁一鍵安裝框架。

沒有記載的旗標名稱會讓伺服器直接拒絕啟動。改了 features 之後附加元件起不來，先把它改回文件列出的那幾個值。

env_vars 的 key 必須符合 ^[A-Z][A-Z0-9_]*$：大寫字母開頭，只能有大寫字母、數字與底線。這裡填的環境變數只給伺服器行程看得到，執行端的模型金鑰各自帶各自的，不會從這裡繼承。金鑰填進去之後會明文顯示在設定分頁上，截圖或螢幕分享前先把那一區收起來。

三種進入方式，差在誰進得來

路徑網址給誰用
側邊欄面板Home Assistant 內建的 Ingress 路徑Home Assistant 使用者，不必知道任何 IP
區域網路直連http://<你的 HA 位址>:8000執行端撥入，以及 omnigent host
Cloudflared 路由https://<你的網域>外網的執行端與遠端使用者

面板走的是 8080 埠，而這個埠鎖死在 Supervisor 的位址，只有 Supervisor 能代理進來，區域網路上的其他機器打不到。真正對外的是 8000 埠。

設了 Cloudflared 路由，記得同時把 base_url 填成那個公開網址。伺服器產生的邀請連結與回呼網址照這個欄位寫；填錯的話連結會指回內網位址，外面的人點了打不開。

面板下的 Settings 有十一個分頁。舊版在面板裡點 Members、Policies、Sharing 會整頁變黑，那是延遲載入的檔案在 Ingress 路徑下抓不到造成的，0.1.15 修好了。看到黑畫面先確認版本。

怎麼確認做對了

五個檢查點。前三項只驗伺服器，後兩項才驗整條路。

  • 側邊欄出現「Woow Omnigent」面板，點進去看得到登入表單
  • 用設定頁的帳密登入成功，左邊出現 New session 到 Usage 四個入口
  • Settings 的十一個分頁逐一點過去都不會變成黑畫面
  • 輸入區底部的主機選單裡至少有一個項目，而且前面是綠點
  • 挑那台主機開一個 session，隨便問一句，代理真的回話

第四項最常卡住：主機清單空的不是壞掉，是這個附加元件本來就不帶執行端。

備份與還原

附加元件備份會把整個 /data 包進去：資料庫叢集、產出的檔案、管理員憑證與所有 session 狀態。日誌與資料庫的預寫日誌被排除在外，因為它們既大又沒有還原價值。

備份模式是冷備份（cold backup）：Supervisor 會先停下附加元件再打包，資料庫不會被拍到寫到一半的狀態，代價是備份期間服務中斷。還原之後資料庫與管理員身分都會回來，執行端會在下一次握手時自己重新註冊，不需要你到每台機器上重跑指令。

備份檔裡有管理員憑證和所有對話內容，跟你的 Home Assistant 快照一樣敏感。不要丟到公開的雲端資料夾。

故障排除

  • 面板打得開，但一直停在登入表單：自動建立管理員那一步跑過了，是你輸入的帳密不對。回設定分頁對照 admin_username 與 admin_password。
  • 主機清單是空的：預期行為，不是故障。附加元件不含執行端，至少要從區域網路或 Cloudflared 路由註冊一台進來。
  • 日誌出現建立管理員失敗的五百錯誤：多半是資料庫根本沒起來。看日誌最上面的初始化區段，錯誤都在那裡。
  • 執行端註冊上了，但對話送出去沒反應：pi 的擴充套件衝突。清掉那台執行端的 ~/.pi-agent/plugins/ 目錄，把 openai-codex 從它的 auth.json 移除，再重新連一次。
  • Settings 的某幾個分頁一片黑：版本舊於 0.1.15。升級即可，不必重裝。
  • 面板一直重新導向、瀏覽器報導向次數過多：也是舊版問題。升到本書鎖定的版本；升級前的暫時解法是改用區域網路的 8000 埠。

常見問題

這個附加元件會不會順便幫我裝好 AI 工具？

不會。它是伺服器版建置，裡面沒有 pi、Claude Code、Codex 的命令列，也沒有執行端。那些東西裝在你另外註冊進來的機器上。這個取捨換到的是映像檔小、啟動快、升級不會連帶動到你的工具鏈。

我可以只用側邊欄面板，不要開 8000 埠嗎？

人可以，機器不行。面板走的 8080 埠只有 Supervisor 進得來，用起來完全沒問題；但執行端是靠 8000 埠撥進來註冊的，關掉就沒有任何機器能接工作。除非你的執行端跟附加元件在同一台機器上，否則 8000 埠必須留著。

附加元件版本 0.1.15 和裡面的 Omnigent 0.12.0 是同一個東西嗎？

不是。0.1.15 是 WoowTech 這個封裝的版本號，記錄的是打包方式與面板修正這類改動；0.12.0 是被包在裡面的上游 Omnigent 版本。升級附加元件不一定會換掉裡面的 Omnigent，反過來也一樣。回報問題時兩個號碼都要講。

我在設定頁改了管理員密碼，重啟之後為什麼登入不了？

因為建立管理員只發生在「還沒有任何管理員」的時候。第一次開機把帳號建好之後，再改設定頁的欄位，重啟時那一步會被略過，資料庫裡的密碼不變。要改密碼請在介面裡改；設定頁那兩欄從此只影響全新安裝或清空資料後的重建。

我跑的是 Home Assistant Container，也能裝這個附加元件嗎？

不行。附加元件是 Supervisor 的機制，純 Docker 版的 Home Assistant 沒有 Supervisor，商店根本不存在。那種情況請走第 21 章的 Rootless Podman 版，它不依賴 Home Assistant，而且自帶一個常駐執行端。
