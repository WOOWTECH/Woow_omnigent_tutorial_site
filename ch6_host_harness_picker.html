第 6 章

Host picker 與 Harness picker：選機器、選代理

為何需要本章

同一句「把這個目錄整理一下」，丟到 A 機器動的是 A 機器上的檔案，丟到 B 機器動的是 B 機器上的檔案。這件事聽起來理所當然，但在聊天視窗用慣的人常常忘記——因為聊天視窗沒有「機器」這個變數。

Omnigent 有兩個變數：在哪裡跑，以及由誰跑。前者是 Host，後者是 Harness 或 Agent。這一章把這兩個選擇器講清楚，包括那個小綠點到底保證了什麼、以及本書對狀態顯示有哪些是不敢亂寫的。

如果你現在畫面上一台機器都沒有，先看第 16 章把主機註冊起來再回來。本章假設至少有一台可選。

核心觀念：地點與人手是兩件事

把一個 session 想成派工單，上面有兩欄要填：去哪裡、找誰。

主機（Host）：實際執行的那台機器。代理讀寫的是這台機器上的檔案，跑的是這台機器上的指令。
框架（Harness）：實際幹活的 AI 編碼工具，例如 Claude Code、Codex、Pi。Omnigent 自己不寫程式，寫程式的是它們。

兩者互相獨立：同一個框架可以派到不同機器上，同一台機器上也可以換不同框架。介面上它們也分屬兩處——Host 在 Composer 下層的第一個選擇器，框架在標著 Runs with 的下拉選單裡。

Host 選擇器：選機器，並看懂那個綠點

Composer 下層由左到右是三個選擇器，第一個就是 Host。實機記錄裡的顯示樣子是機器名稱前面帶一個綠點，例如 Pi Web ChatGPT (pi5)。

綠點的意思是這台機器目前連著。同一個線上狀態在設定裡的 Import sessions 頁也看得到，那裡的 Machine 欄位會在機器名稱旁邊直接標一個 ONLINE 徽章。兩處是同一件事的兩種畫法。

狀態畫面上怎麼顯示本書查證狀況
線上Host 選擇器：機器名稱前一個綠點已於 2026-09-09 實機確認
線上Import sessions 頁：機器名稱旁 ONLINE 徽章已於 2026-09-09 實機確認
離線未記錄本書未查證：該次記錄中所有機器都是線上，沒有拍到離線時的樣式
忙碌未記錄本書未查證：沒有觀察到獨立的忙碌標示

本書不替離線與忙碌編一個圖示出來。實務上的判斷法是反過來的：沒有綠點就當它不能用。要確認機器到底怎麼了，看的是第 18 章的 Runner 排錯流程，不是盯著這個選擇器猜。

Runs with：十一個框架與四個代理

Runs with 下拉選單分成兩區。上面一區是框架，下面一區是代理。

區塊直接列出的項目收在子選單的項目
Harnesses（共 11）Claude Code、Codex、PiMore 底下：OpenCode、Cursor、Antigravity、Kiro、Qwen Code、Goose、Kimi、Hermes
Agents（4 加自訂）Polly（Multi-agent coding）、Debby（Multi-agent debate）、Grok Build、DevinCustom agents 子選單

兩區的差別，從實機記錄能確定的是分類與名稱本身：Polly 標為多代理協作寫程式、Debby 標為多代理辯論。也就是說代理這一區裡至少有一部分是「一個名字底下跑多個代理」的組合，而不是單一工具。更細的行為差異在第 17 章。

needs setup 徽章

沒有在該主機上設定好的項目，名稱旁邊會有一個橘色的 needs setup 徽章。這個徽章是跟著主機走的：同一個框架在 A 機器設定好了，在 B 機器上仍然可能標著 needs setup。

清單太長看不下去的話，到 Settings → Appearance 打開 Hide unconfigured harnesses。開啟後這些標著 needs setup 的項目會被整個隱藏，而不只是繼續標記。只用一兩種框架的人建議開，選單會短很多。

怎麼挑：三個問題定生死

不需要背十一個框架的特性。每次派工照順序回答三個問題就夠了。

問題對應的選擇器答錯的後果
這件事要動哪台機器上的檔案？Host代理在對的目錄名底下動了錯的機器的檔案
那台機器上，是哪個資料夾？工作目錄（下層第二個）找不到檔案，或動到不該動的範圍
這件事適合誰做，成本可接受嗎？Runs with做得出來但花太多，或框架沒設定好直接卡住

第三個問題沒有標準答案，但有一個實用的迭代法：先用你已經設定好、沒有 needs setup 徽章的那一個跑通，跑完之後到 Usage 頁看 Cost by harness 與 Cost by model，知道這類任務的實際單價之後，再決定要不要換。用猜的挑框架不會比看帳單準。

工作目錄與 Worktree

下層第二、三個選擇器決定代理動手的範圍。第二個是工作目錄，實機記錄的例子是 home；第三個是 工作樹（worktree），決定要不要在 git 專案裡另開一份來改。

兩個相關的全域設定在 Settings → Git：

  • Always use a random worktree：在任何 git 工作區開新 session 時，一律以隨機命名的新 worktree 起始。注意 Project 自己的 Random worktree 設定會覆寫這個全域值。
  • Default base branch：命名新 worktree 分支時自動填入的基底分支。留空就不自動填。

開始之前

本章的操作步驟需要：

  • 至少一台 Host 在選擇器裡顯示綠點
  • 那台 Host 上至少有一個框架沒有 needs setup 徽章
  • 一個你願意讓代理讀取的目錄。第一次練習不要挑正在上線的專案

選 Host 等於把某台機器的檔案交給代理。挑機器之前先想清楚那台上面有什麼，特別是家目錄。分享設定裡有一個 Read only (restricted) 模式，就是專門針對「工作目錄是家目錄或檔案系統根」的 session 加嚴限制的（第 9 章），這說明產品自己也把這種範圍視為高風險。

派一個任務到指定機器與指定框架

  1. 先看清楚選擇器裡有幾台機器

    在 Composer 點下層第一個選擇器，把清單整個看過一遍。記下哪些有綠點、哪些沒有。沒有綠點的先當它不存在，本步驟不要試著去救它。

  2. 挑一台有綠點的機器，並確認它是你以為的那台

    機器名稱可能長得很像（實機記錄裡就有 pi1 與 pi5 這種只差一個數字的命名）。挑錯機器的後果不是報錯，是安靜地在錯的地方做對的事，這比報錯難發現。

  3. 設定工作目錄與 Worktree

    第二個選擇器挑資料夾。如果這是一個 git 專案而且你要改程式碼，第三個選擇器另開 worktree。不確定要不要開的話，改程式碼就開，只讀檔案就不用。全域預設可以在 Settings → Git 調整。

  4. 打開 Runs with，挑一個沒有 needs setup 的框架

    前三個（Claude Code、Codex、Pi）直接列在外面，其餘八個收在 More 底下，代理則在下面那一區。第一次就挑那個沒有橘色徽章的，不要為了試新東西卡在設定上。

  5. 送出一個可驗收的小任務，然後回頭對帳

    用一個只讀不寫的任務跑通，例如列出該目錄下的檔案。跑完之後到 Usage 看 Cost by harness 與 Cost by model，把「這台機器 + 這個框架」的實際單價記下來。這一步做過一次，之後挑框架就有依據了。

怎麼確認選對了

選對機器與框架的驗收方式不是看設定畫面，是看代理的第一個回合。

  • 代理列出來的檔案，跟你在那台機器上預期看到的一致
  • 它沒有一開頭就抱怨找不到目錄或沒有權限
  • Runs with 顯示的框架名稱，跟你以為自己選的那個相同
  • 跑完之後 Usage 的 Cost by harness 裡多出來的那一筆，記在你選的那個框架名下

故障排除

  • Host 選擇器裡一台機器都沒有：代表還沒有任何主機註冊上來，或全部斷線。這不是選擇器的問題。註冊流程在第 16 章，連線排查在第 18 章。
  • 機器在清單裡，但名稱前面沒有綠點：當它不可用。本書未查證離線狀態的視覺樣式，所以請不要用「有沒有變灰」之類的特徵去判斷；有綠點才選是唯一可靠的規則。
  • 想用的框架標著橘色 needs setup：這個框架在這台機器上沒設定好。兩個選項：換一個沒有徽章的，或依第 17 章把它設定起來。注意換一台機器同一個框架也可能一樣標著徽章。
  • Runs with 選單太長，找不到想要的項目：前三個之外的八個框架收在 More 子選單裡，自訂代理收在 Custom agents 子選單裡，不在第一層。要一次減短清單，開 Settings → Appearance 的 Hide unconfigured harnesses。
  • 代理找不到檔案，但你確定檔案在：先確認機器對不對，再確認工作目錄對不對，最後確認是不是開了 worktree 而代理正看著另一份。這三件事按順序查，不要跳。
  • 排程任務跑在你沒預期的機器上：Automations 的 Host (optional) 欄位預設是 Resolve at fire time，意思是觸發當下才決定跑在哪台已連線的主機上。要指定機器就在那個欄位明確選一台，細節在第 10 章。

常見問題

十一個框架我得全部設定起來嗎？

不用，多數人長期只用一到兩個。沒設定的會標 needs setup，看了礙眼就到 Settings → Appearance 打開 Hide unconfigured harnesses 把它們藏起來。要不要加第二個框架，等你在 Usage 頁看過成本、或現有的那個在某類任務上明顯不順手的時候再說，第 17 章有比較材料。

Harness 跟 Agent 這兩區到底差在哪？

從 2026-09-09 的記錄能確定的是分區與名稱：框架區有 11 個既有的 AI 編碼工具，代理區有 4 個加上自訂項，其中 Polly 標為多代理協作寫程式、Debby 標為多代理辯論。也就是代理區至少有一部分是把多個代理組起來的產物。本書沒有逐一實測它們的行為差異，不會替它們寫效果比較；第 17 章會處理這個題目。

綠點是不是代表這台機器一定能順利跑完任務？

不是。綠點只保證連線，不保證那台機器上有你要的框架、有足夠磁碟、或有存取那個目錄的權限。連線正常但框架沒設定好，你會在 Runs with 那邊看到 needs setup；連線正常但目錄不對，你會在代理的第一個回合看到它找不到檔案。這三個條件要分開檢查。

選錯機器已經送出了，會怎樣？

代理會在那台機器上照你的指示做事。如果任務是只讀的，後果只是白花一點錢；如果任務會改檔案，那就是在錯的機器上真的改了。這是本章一再強調先確認機器再打字的原因。發現選錯時先按 Esc 停止回應（第 5 章），再到 Workspace 面板看它動了什麼（第 7 章）。

本章的設定會影響 Automations 排程任務嗎？

會，但欄位不同。排程任務在自己的新建對話框裡有 Runs with，也有 Host (optional)；後者預設是 Resolve at fire time，也就是觸發當下才挑一台連線中的主機。另外 Settings → Git 的 worktree 預設是全域的，Project 層級的設定會覆寫它。排程細節在第 10 章。
